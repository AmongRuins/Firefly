## Fiddler 简介

Fiddler 作为`代理服务器`的方式存在客服端和服务器之间，所有的网络数据都要经过 Fiddler，以此截取数据信息，实现网络数据抓包。


Fiddler 是位于客户端和服务器端的 `HTTP 代理`，监听两者发出的请求响应信息，是目前最常用的 HTTP 抓包工具之一。

功能非常强大，是 web 调试的利器：
- 监控浏览器所有的 HTTP/HTTPS 流量
- 查看、分析请求内容细节
- 伪造客户端请求和服务器响应
- 测试网站的性能
- 解密 HTTPS 的 web 会话
- 全局、局部断点功能
- 可以安装第三方插件扩展额外功能

适合场景：
- 接口调试、接口测试、线上环境调试、web 性能分析
- 判断前后端 bug、开发环境 hosts 配置、mock、弱网断网测试

## HTTP 简介

Hyper Text Transfer Protocol（超文本传输协议），用于从万维网服务器传输超文本到本地浏览器的传送协议。

HTTP 协议是基于 TCP 的应用层协议，它不关心数据传输的细节，主要是用来`规定客户端和服务端的数据传输格式`，最初是用来向客户端传输 HTML 页面的内容。默认端口是 80。
> HTTP 是基于请求与响应模式的、无状态的、应用层的协议

### 请求报文

HTTP 请求报文（Request Message）是`客户端（浏览器、APP、爬虫等）向服务器发起 HTTP 请求时，按照 HTTP 协议规范发送的结构化数据`，用于告知服务器「`要做什么、要什么资源、带什么参数 / 数据`」。

一个完整的 HTTP 请求报文，顺序固定不可调换，分为4 个核心部分：`请求行 → 请求头 → 空行 → 请求体`。

**请求行（Request Line）**：请求报文的第一行（唯一一行），是整个请求的核心摘要，固定格式如下：`<请求方法> <请求URI/URL> <HTTP版本>`，例如：`GET /api/user/info?user_id=10086 HTTP/1.1`。

**请求方法**：HTTP 标准动词，明确告知服务器要执行的操作，高频常用项如下：
| **请求方法**    | **核心含义**   | **典型使用场景**                                         |
|-------------|------------|----------------------------------------------------|
| **GET**     | 资源获取（只读操作） | 打开网页、查询接口、获取图片 / 静态资源，`默认无请求体`，参数放在 URL 的 Query 查询串中 |
| **POST**    | 资源提交 / 创建  | 登录、表单提交、新增数据接口，`核心参数放在请求体中`                          |
| **PUT**     | 资源全量更新     | 修改用户全量信息、覆盖整条数据                                    |
| **DELETE**  | 资源删除       | 删除数据接口                                             |
| **HEAD**    | 仅获取响应头     | 检查资源是否存在、校验缓存有效性，无响应体                              |
| **OPTIONS** | 跨域预检请求     | 跨域请求前浏览器自动发起，询问服务器允许的请求源 / 方法                      |
| **PATCH**   | 资源部分更新     | 仅修改资源的单个字段，无需全量提交                                  |

**请求 URI/URL**：统一资源标识符，明确告知服务器要访问的目标资源位置
- 绝对路径形式（最常用，配合 Host 头）：/api/user/info`?user_id=10086`
- 完整 URL 形式（代理请求专用，Fiddler 抓包可直接看到）：https://www.example.com/api/user/info?user_id=10086
- 补充：`?`后为 Query 查询参数，多组参数用&分隔，是 GET 请求传参的核心方式

**HTTP 版本**：客户端使用的协议版本，常见为HTTP/1.1（最通用，强制要求携带 Host 头）、HTTP/2、HTTP/3

---

**请求头（Request Headers）**：请求行下方，多行`字段名: 字段值`格式的键值对（每行一个字段，大小写不敏感），用于传递请求的元数据，告知服务器「`客户端是谁、能接受什么内容、带了什么凭证`」。

高频核心请求头按功能分类如下：
| **分类**          | **关键字段**        | **核心作用**                                         | **典型示例**                                                               |
|-----------------|-----------------|--------------------------------------------------|------------------------------------------------------------------------|
| **强制必填 & 基础定位** | Host            | 目标服务器的域名 + 端口，HTTP/1.1 协议强制必填，用于服务器区分同 IP 下的多个站点 | `Host: www.example.com`                                                  |
| ****            | Connection      | 连接管理，控制 TCP 连接是否保持长连接                            | `Connection: keep-alive`                                                 |
| **客户端标识**       | User-Agent      | 客户端信息（浏览器、系统、设备、APP 标识），俗称 UA，常被用于反爬校验           | `User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) Chrome/120.0.0.0` |
| **内容协商 & 解析**   | Accept          | 客户端能接受的响应体媒体类型                                   | `Accept: application/json, text/html, */*`                               |
| ****            | Accept-Encoding | 客户端支持的响应体压缩格式                                    | `Accept-Encoding: gzip, deflate, br`                                     |
| ****            | Content-Type    | 请求体的媒体类型 / 格式，服务器必须按此解析请求体，POST 请求必填             | `application/json; charset=utf-8`                                        |
| ****            | Content-Length  | 请求体的字节长度，服务器据此读取完整的请求体                           | `Content-Length: 58`                                                     |
| **鉴权 & 会话凭证**   | Cookie          | 客户端自动携带的 Cookie，用于会话保持、登录状态校验                    | `Cookie: token=abc123; uid=10086`                                        |
| ****            | Authorization   | 接口鉴权凭证，常用 Bearer Token、Basic Auth                | `Authorization: Bearer abc123xyz456`                                     |
| **缓存 & 溯源**     | Referer         | 发起当前请求的来源页面 URL，用于防盗链、请求溯源                       | `Referer: https://www.example.com/login.htm`l                            |
| **跨域相关**        | Origin          | 跨域请求的源域名，浏览器自动携带，不可手动篡改                          | `Origin: https://www.example.com`                                        |

---

**空行**：请求头和请求体之间，`必须有一个单独的空行`（**连续两个回车换行符\r\n\r\n**），是 HTTP 协议的强制规范，用以`明确标识请求头结束，请求体开始`。

哪怕没有请求体，请求头结束后也必须携带这个空行，否则服务器会直接解析失败，返回 400 错误。

---

**请求体（Request Body）**：也叫请求正文，是客户端发送给服务器的`实际业务数据`，是 POST/PUT/PATCH 等请求的核心，GET/HEAD 请求默认无请求体。
- 格式完全由请求头的 Content-Type 决定，二者必须严格匹配，否则服务器会解析失败、无法接收参数。
- 为可选内容，仅在需要提交数据时携带

抓包最常见的 3 种请求体格式：
1. `application/json`：目前接口开发最主流的格式，请求体为标准 JSON 字符串。例如：`{"username":"test_user","password":"123456","remember":true}`。
2. `application/x-www-form-urlencoded`：表单默认提交格式，和 URL 查询串格式一致，键值对用&分隔。例如：`username=test&password=123456&remember=1`。
3. `multipart/form-data`：文件上传专用格式，支持二进制文件和普通参数混合提交，通过 boundary 分隔符区分每个字段

### 响应报文

HTTP 响应报文（Response Message）是服务器收到客户端 HTTP 请求后，按照 HTTP 协议规范返回的结构化数据，用于告知客户端请求的`处理结果`、携带`返回的资源内容`。

一个完整的 HTTP 响应报文，严格遵循 RFC 7230 协议规范，分为 4 个核心部分，顺序固定：`状态行 → 响应头 → 空行 → 响应体`。

**状态行（Status Line）**：响应报文的第一行，是整个响应的核心摘要，直接告诉客户端请求的`最终处理结果`，固定格式：`<HTTP版本> <3位状态码> <状态描述短语>`，例如 `HTTP/1.1 200 OK`。

**HTTP 版本**：与请求报文的版本对应，常见为 `HTTP/1.1、HTTP/2、HTTP/3`。

**状态码**：3 位数字，是请求结果的核心标识，分为 5 大固定类别：
| **分类**  | **核心含义**      | **高频常用值**                                                        |
|---------|---------------|------------------------------------------------------------------|
| **1xx** | 信息性响应，协议中间状态  | 101（协议切换，如 WebSocket）                                            |
| **2xx** | 请求成功处理        | 200 OK（成功）、201 Created（资源创建成功）、204 No Content（无返回体）              |
| **3xx** | 重定向，需客户端进一步操作 | 301（永久重定向）、302（临时重定向）、304（缓存生效，无响应体）                             |
| **4xx** | 客户端错误，请求有问题   | 400（参数错误）、401（未授权 / 未登录）、403（权限不足，服务器拒绝）、404（资源不存在）、405（请求方法不允许） |
| **5xx** | 服务器错误，服务端处理失败 | 500（服务器内部错误）、502（网关错误，上游服务异常）、503（服务不可用）、504（网关超时）               |

**状态描述**：对状态码的简短文本说明，仅用于人类阅读，不影响程序处理。

---

**响应头（Response Headers）**：状态行下方，多行`字段名: 字段值`格式的键值对，每行一个字段，用于传递响应的元数据，告诉客户端如何处理返回的内容。

常用核心响应头按功能分类如下：
| **分类**         | **关键字段**                    | **核心作用**                                                                                                        |
|----------------|-----------------------------|-----------------------------------------------------------------------------------------------------------------|
| **基础通用类**      | Server                      | 服务器软件信息（如 nginx、Apache）                                                                                         |
| ****           | Date                        | 响应生成的标准 GMT 时间                                                                                                  |
| ****           | Connection                  | 连接管理（keep-alive 长连接 /close 关闭连接）                                                                                |
| **内容解析类（最核心）** | Content-Type                | 响应体的媒体类型 + 字符集，决定客户端如何解析内容例：application/json; charset=utf-8（JSON 接口）、text/html; charset=utf-8（网页）、image/png（图片） |
| ****           | Content-Length              | 响应体的字节长度                                                                                                        |
| ****           | Content-Encoding            | 响应体压缩格式（gzip/br/deflate），客户端需对应解压                                                                               |
| **缓存控制类**      | Cache-Control               | 缓存策略（max-age=3600 缓存 1 小时 /no-cache 协商缓存 /no-store 不缓存）                                                         |
| ****           | ETag                        | 资源唯一标识，用于协商缓存                                                                                                   |
| ****           | Last-Modified               | 资源最后修改时间，用于协商缓存                                                                                                 |
| **安全 & 跨域类**   | Access-Control-Allow-Origin | 跨域允许的请求源（* 代表所有，或指定域名）                                                                                          |
| ****           | Set-Cookie                  | 服务器给客户端写入 Cookie，后续请求会自动携带                                                                                      |
| ****           | X-Frame-Options             | 控制是否允许被 iframe 嵌入，防点击劫持                                                                                         |
| **重定向类**       | Location                    | 重定向的目标 URL，3xx 状态码必须携带                                                                                          |

---

**空行**：响应头和响应体之间，`必须有一个单独的空行`（**连续两个回车换行符\r\n\r\n**），是 HTTP 协议的强制规范，作用是`标识响应头结束，响应体开始`。

---

**响应体（Response Body）**：也叫响应正文，是服务器返回的`实际业务数据`，也是抓包时最关注的核心内容。
- 格式完全由响应头的 `Content-Type` 决定，常见类型：HTML 网页、JSON 接口数据、JavaScript/CSS 文本、图片 / 视频 / 文件等二进制数据
- 响应体为`可选`内容：204 No Content、304 Not Modified、HEAD 请求的响应，均无响应体
