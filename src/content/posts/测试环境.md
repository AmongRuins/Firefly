## 一、什么是测试环境
测试环境：用来执行软件测试、跑用例、找 bug，**专门搭建的一套软硬件 + 网络 + 数据 + 依赖服务**的完整环境。

组成 = **硬件 + 软件 + 网络 + 数据库 + 测试数据 + 第三方依赖**

1. 硬件：服务器、电脑、手机、打印机等
2. 软件：操作系统、浏览器、中间件、APP 版本
3. 网络：内网、外网、弱网、4G/5G
4. 数据库：测试库、基础数据
5. 测试数据：账号、商品数据、订单数据
6. 依赖系统：支付、接口、第三方服务

测试环境能干什么：
- 执行功能测试、接口测试、性能测试
- 重现 bug、验证 bug
- 做回归测试
- 做异常、压力、极限测试

常见的三种测试环境：
- **开发环境（dev）**：开发写代码用，不稳定，不适合测试
- **测试环境（test/uat）**：测试专用，干净、稳定，用来跑用例、测功能
- **生产环境（prod / 线上）**：用户真实使用，**绝对不能随便测**

不能在生产环境测试的原因：
1. 会影响真实用户
2. 会产生脏数据、弄坏订单
3. 有资金风险、安全风险
4. 违法、泄露用户隐私

总体来说，测试环境就是**模仿线上、独立隔离、专供测试使用、安全可控、可以反复测试的一套运行环境**

## 二、测试环境的设计原则

1. 独立性原则

测试环境和开发环境、生产环境**分开**，互不干扰，不能混用

测试环境要干净、独立、排除干扰（更好的定位问题）

2. **一致性原则（最重要）**

测试环境尽量**和线上生产环境配置一致**（系统、版本、数据库、硬件、网络），保证测出的问题真实有效

尽可能少用模拟器（安卓系统）和虚拟机（电脑系统）

- app：最少能够支持的安卓版本（当前最新版本往下走三四个版本）
- ios：当前的手机往下走三四个版本，再选择一个最低的版本
- web：最低能够支持的浏览器版本（win10，win7、win8，winxp）根据项目的不同，可能还需要考虑其他测试环境

需要结合用户需求、市场定位等多种因素，优先选择主流的、广泛普及的操作系统（win/mac）和软件平台

3. 可复用原则

环境可以反复使用、快速搭建、支持回归测试，不用每次重做

4. 可控性原则

测试人员能自己管理环境：启停服务、改数据、清缓存、看日志、控制权限

5. 隔离性原则

不同项目、不同测试轮次、不同人员的测试数据互相隔离，不互相影响

6. 可还原原则

测试做完可以一键恢复初始状态，方便下一轮测试

7. 安全性原则

不能用真实敏感数据，防止泄露；权限受控，不能影响线上

8. 低成本、高效率原则

资源合理利用，不要过度高配，快速部署、省时省力

总的来说，测试环境要做到：**独立隔离、和生产一致、可控可还原、安全可复用、低成本高效率**
